## Goals / Non-Goals

**Goals:** useful rectangular data distribution; exactly-once effects with shared traffic cost; bounded backpressure and justified drain; real scalar values sufficient for synchronization; one physical resource registry across both fabrics and compute; an explicit finite producer/consumer example; independent validation and compatibility evidence. All hardware sizes and effective timings remain configurable.

**Non-Goals:** arbitrary destination masks; wrapping rectangles or arbitrary source entry; multicast reads or atomics; linked packets, priorities, adaptive routing or hardware reservation retries; scalar decrement/reset/CAS/general ALU; tensor reductions or values; hardware semaphore/ISA/kernel execution; arbitrary dynamic task graphs; interchip/host/PCIe behavior; new ML/RL contracts; ttsim execution or silicon timing calibration. Generic shapes and widths do not imply that every shape or width is legal on the Wormhole profile.

## Decisions

### 1. Separate finite admission and opt-in contracts

Add `kind: multicast_sync_workload`, `schema_version: 1`, policy `finite_multicast_sync_v1`, and a separate `multicast_sync_result` v1. Proposed modules are `configs/schemas/multicast_sync.py`, `multicast_plan.py`, `multicast_tree.py`, `multicast_transport.py`, `scalar_sync.py`, `multicast_sync_runtime.py`, `multicast_sync_records.py` and `replay_multicast_sync.py`. Split a module when a concrete responsibility warrants it.

The workload declares the existing graph/profile source, fabric/endpoint bindings, addressed buffers, memory/link/router settings, finite unicast/local memory operations, multicast writes, scalar definitions/increments/waits, and optional finite compute streams. Reuse existing dtype/rate/worker/stream record types for compute. The new enclosing compiler owns mixed-operation version and stage validation; do not disguise multicast-produced inputs as initially ready in a v1 compute workload. Every operation and generated packet has a unique stable identity. No caller-supplied callbacks or dynamic submission are accepted.

Strict parsing and pure compilation validate all nested documents, units, profile restrictions, resource aliases, permissions, address extents, generated routes, positive representable durations and the combined dependency graph before constructing SimPy objects or replacing output files. Canonical input/effective-plan hashes include all policy settings and source identities. Path resolution follows the declaring document. Existing schemas keep their version dispatch and unsupported-mode errors.

**Alternative:** reinterpret the old `TransType.MULTICAST` or `sync_mode` fields. Rejected: those fields lack addressed recipients, service ownership and observable completion and would broaden legacy inputs silently.

### 2. Define a small rectangular tree exactly

Use `corner_rectangle_tree_v1` with required `major_axis: x|y`, fabric-coordinate inclusive `start`/`end`, and explicit `include_source`. The admitted fabric already has canonical physical-to-fabric translation and positive-direction links. Bounds satisfy `0 <= start <= end < extent` on each axis. Translating a physical rectangle into the opposite fabric must translate both corners and normalize its bounds; it must resolve to the same intended physical recipients.

For X-major, require source `sy == start.y` and `sx <= start.x`. Build an X approach from source to `(start.x,start.y)`, a Y spine from that entry to `(start.x,end.y)`, and an X branch along every rectangle row to `end.x`. For Y-major, exchange X and Y: source `sx == start.x`, `sy <= start.y`, Y approach, X spine, then Y branches. The approach may be empty. Degenerate rows/columns and a one-recipient local case are legal. No admitted tree edge wraps. Source inside the rectangle is supported only at the entry corner.

All structural tree edges remain explicit, including transit through nonworker positions. Nonworker tiles never receive a write. Eligible recipients are the enabled worker L1 attachments inside the rectangle, one per physical worker on the selected fabric, minus the source when excluded. Reject rectangles containing a worker whose required L1 endpoint is unavailable or whose compute availability is disabled/unresolved; do not silently shrink such a destination set. Nonworker transit routers must still be enabled. The source must be an enabled worker with local readable L1 and injection permission. The final set must be nonempty, and its explicit target-buffer bindings must match exactly. Duplicate aliases do not create extra recipients.

Each write has one positive length and one target byte address common to all recipients; bindings resolve that address into each recipient's reservation. All target extents must fit and be writable. Source-included writes use disjoint source and target extents. Arbitrary destination lists are not a second routing mode. A rectangle representing broadcast follows the same rules; a request to broadcast to every router or to memory/host endpoints is unsupported.

Stable tree-edge/branch identities are qualified by operation, segment and fabric. A branch is a continuation of one logical packet, not an independently injected copy. Compile an arborescence with one incoming edge per nonroot router, no reconvergence or repeated edge, and exactly one local ejection for each recipient. Validate every edge against the canonical graph and export parent/child edges plus expected recipient membership. An opt-out leaf with no recipient terminates each arriving flit through a bounded router stage and returns its input credit; emit a tree-terminal event, never a payload delivery or memory write. Its structural link traffic still counts. A plain union of XY/YX unicast routes is not this policy.

**Alternative:** all rectangular hardware paths immediately, including wrapped destinations and arbitrary sources. Deferred because it expands coordinate cases and dependency analysis without being necessary for the first distribution fixture. The selected policy is explicitly narrower than general hardware broadcast routing.

### 3. Shared flits with bounded tree reservation

Select `atomic_tree_reservation_v1`. Add a multicast-only virtual lane/packet-owner namespace on the same `VirtualChannelLink` serializers and router pipelines as ordinary requests/responses. Keep new internal identities distinct from public v2 envelopes; preserve the exact old public request/response contracts and serialization. Composite internal link contracts admit the union of precompiled unicast and tree packets and validate branch identity without forging a unicast destination.

Before one segment begins injection, a bounded FIFO reservation controller acquires every required multicast lane owner as one all-or-none grant. A failed attempt holds no subset. Conflicting trees wait; disjoint trees can progress. Grants wait only for required resources and their declared prerequisites, not for a later operation or a response. A finite configured controller capacity and positive setup/per-tree-edge ACI cost model reservation overhead. This is a centralized logical abstraction: it emits reservation events and consumes its own control resource, but invents no physical setup packets or register timing. Reports separate this assumed overhead from data/response channel bytes.

For each incoming flit, retain one charged input token and a bounded pending-output bitset. Send at most one copy per required child/ejection, in deterministic order, as downstream credit becomes available. Acquire downstream storage before a router-stage grant; release the stage after its finite transfer. Release the input credit only after every required output has accepted that flit. Never put payload copies into uncounted SimPy waiters or Python lists. Replication staging capacity is explicit and charged; route/destination/control metadata may scale with the finite input inventory. Backpressure from a slow child may stall siblings once bounded staging fills; this is declared behavior, not a loss or retry.

Release the tree grant only after that segment's tree flits, ejections and delayed credit returns drain. Ack traffic has separate response lanes and need not retain the grant. Each physical channel serializes all admitted lane classes under the existing fair arbitration, with configurable clock conversion, directed slowdown and propagation behavior. Separate virtual lanes never multiply the physical bandwidth.

**Dependency argument:** an admitted tree is acyclic; conflicting multicast trees cannot simultaneously own the same multicast lanes, and a waiting tree owns none. Unicast/response lane dependencies retain the existing validated dateline policy. Physical serializers/router stages have finite service and never hold a grant while waiting for another resource. Endpoint services finish without waiting for a later signal or network request; response descriptors are bounded and reserved before an acknowledgement-producing segment is injected. A consumed request does not retain incoming credits while acquiring response storage. Responses never wait for multicast reservations. Together with the finite operation/slot DAG and pre-admitted access conflicts below, there is no backwards resource edge closing a wait cycle. Tests stress this argument; a watchdog alone is not its proof.

**Alternative:** reuse unicast dateline ranks for multicast without analysis. Rejected because branch paths introduce different turns and multi-output ownership. Whole-tree reservation is conservative and can reduce concurrency; it is not claimed to reproduce hardware VC utilization or randomized reservation retries.

### 4. Addressed writes, segmentation and completion

Use the existing configurable header/payload/flit segmentation arithmetic once per logical source segment. Source L1 reads each useful byte once. Each admitted tree channel carries the segment's header and rounded data flits once; local ejection at each recipient is a separate channel. Each recipient writes all useful bytes through its own canonical `MemoryResource` and `MemoryService`. Source inclusion adds an ejection and real L1 write, not another source read. Header/padding/control bytes consume network service but are not payload memory writes.

Before injection, obtain all required source/destination access leases and bounded responder descriptors using nonblocking all-or-none bundle acquisition; failed attempts roll back without publishing data, retaining leases or acquiring a tree grant. The mixed compiler checks physical-range conflicts, producer versions and slot-reuse edges conservatively. Destination service cannot depend on a consumer's later semaphore wait. Publication uses the existing version owner and recipient-specific `(operation, generation)` identity. Consumers need their complete declared extent, not merely the first arriving flit.

Expose acceptance, source-read completion, injection handoff, each recipient's visible effect, each returned acknowledgement, source-observable completion, all-effects completion and resource drain separately. `write_posted` completes locally when all source segments have handed off; this permits source reuse only after its read leases release and gives no remote visibility observation. `write_acknowledged` completes only after all recipients' per-segment acknowledgements return over admitted unicast response paths. Acknowledgements are emitted after the corresponding destination service. Overall operation target visibility requires all segments for that recipient. Global run success requires all effects/responses and resources to drain, including posted operations.

No implicit cross-fabric issue ordering is promised. Explicit local dependencies or acknowledged completion establish source-side order. A target may use its own local publication; an initiator cannot consume a remote `all_effects` diagnostic as a zero-cost fence. Unsupported linked/static-VC semantics remain rejected.

**Alternative:** issue one unicast write per destination. Rejected because it rereads the source and overcharges shared-prefix traffic. Conversely, counting only the source payload ignores destination service and branch wires.

### 5. Scalar counters and indivisible shared service

Use `monotonic_l1_counter_v1`: an explicitly initialized unsigned counter at an aligned local L1 address, `atomic_increment` by exactly one, and an optional previous-value return to a separately reserved initiator L1 inbox. Storage width is explicit; generic profiles admit 8/16/32/64-bit scalar words that fit the declared inline-control format, while the Wormhole binding requires aligned 32-bit words. Reserve the full configured atomic access granule, not only a disconnected Python integer. Atomic granules cannot overlap other counters, payload buffers or return inboxes. Access-granule and service assumptions are explicit; no bank-level model is inferred.

Admit only finite monotonic programs whose initial value plus all potential increments fits the word. Reject overflow, negative values, reset/decrement, unsupported immediate increments and CAS. This permits deterministic threshold reasoning without emulating an unreviewed opcode/wrap encoding. The scalar ledger retains actual integer values; payload tensors remain abstract.

Remote increments use existing admitted unicast routes and their request/response classes. The immediate request is one physical control flit; returning mode also sends one response flit with the old scalar value inline, provided it fits the admitted control geometry. A posted increment has no response. No source memory read is invented for an immediate. Returning mode reserves its local inbox and writes the old value through real local service before source completion.

Extend the shared memory server with an opt-in indivisible RMW service job. It occupies the same bounded FIFO server used by reads/writes, with explicit positive `atomic_native_cycles` converted once to ACI cycles. This is the final effective service duration, not an extra delay on top of separately charged read and write jobs. Trace its addressed read/write granule counts independently of that duration. Both fabrics and local clients reach the same canonical server. At service completion, read the old value, increment once, publish the new value and sequence number, then release the job; queued updates cannot observe an intermediate state. Ordering is server admission order with deterministic simultaneous-arrival ties, not producer issue order or a chip-wide atomic lock. Different L1 owners may progress concurrently.

Posted local completion is request handoff, distinct from the scalar's target-visible update. Returning completion requires visible update, response transport and inbox service. Request credits and atomic server ownership are released before waiting for return traffic. Every accepted increment has at most one linearization event and one resulting value transition; resuming a run never repeats it.

**Alternative:** a separate per-counter delay resource. Rejected because it creates free L1 capacity/bandwidth and misses contention with the workload. The aggregate server conservatively serializes even independent counters on the same L1; detailed bank parallelism needs a future policy.

### 6. Local waits and causal finite pipeline composition

Use `local_threshold_wait_v1`, with a required counter, `value >= threshold`, and explicit local data-ready prerequisites. The waiter belongs to the same physical worker/L1 as the counter. An initial local observation and an observation after a value-change notification consume configured local read/control service. The condition is evaluated after that service; monotonic counters avoid missed transient equality. Event subscription/recheck must not lose an update arriving while an observation is pending. No periodic busy polling, remote memory peeking or hardware semaphore instruction is implied.

A blocked wait owns finite control metadata only, not a network credit, atomic server slot, compute context or tree grant. Data-buffer slots can remain charged to their admitted generation, and their reuse dependencies participate in cycle checking. A signal count alone does not publish payload data. A consumer releases only after a serviced local observation satisfies the threshold and every required local data extent has the correct producer version/generation.

The mixed compiler expands memory, multicast, scalar, waits and finite compute streams into one closed operation/stage/slot DAG. Each wait names a finite set of admitted increment producers that can satisfy its threshold; reject unknown/cyclic dependencies, unreachable thresholds and slot cycles. Named producers are admission evidence, not runtime filtering of a counter by sender: all updates to that address change the same value. Barrier declarations therefore require the DAG to exclude later-phase or unrelated increments from satisfying an earlier phase's threshold. A producer may signal after its own source-observable acknowledged data completion, or a recipient may signal after its own local data publication. A posted source handoff is not sufficient for a remote consumer's data-ready proof. No dependency can use a remote diagnostic event as local control.

Refactor compute stage construction into an attachable component receiving the shared environment, admitted plans, existing memory owners and typed activation capabilities. The existing standalone runtime continues to construct and own these objects as before. The mixed runtime owns one transport registry, memory registry, scalar ledger, compute pools and finalizer. Use public lifecycle accessors and capability tokens; do not inspect private event dictionaries or create one independent simulator per stage. Reuse existing compute cost and bundled FIFO-slot semantics. Imported multicast data enters the intended A/B slot generation without a duplicate unicast reader transfer; local operand reads and result writes still consume memory service.

The representative workload has one source distribute an operand to at least two worker slots, each worker wait for local data/notification, compute an admitted FC/matmul job, and send an increment to a collector's L1 counter after its required output completion. The collector releases at the declared threshold. A two-generation variant exercises slot reuse and increasing thresholds without resetting counters: the distributor also owns the collection counter and starts the next round only after its local previous-round wait completes. Later-round signals cannot overtake an earlier barrier. A different remote distributor would require an explicit return notification. Separate unicast control/data traffic shares links and memory during the run.

**Alternative:** connect two completed replay results using timestamps or global SimPy events. Rejected because this omits contention and allows remote completion to act as a free notification.

### 7. Results, validation, compatibility and finite failure states

`multicast_sync_result` v1 records admitted policies/configuration/source identities, expected and observed recipients, trees, branch/flit/credit events, reservation and descriptor occupancy, shared physical-channel launches, addressed source/destination service, scalar transitions, local observations, release prerequisites, compute stages/generations and pending state. Distinguish source logical bytes, aggregate recipient bytes, tree packet bytes, physical channel bytes and atomic service traffic. Diagnostic all-effects events are labeled as observations, not legal initiator wait conditions.

Snapshots at a finite absolute ACI horizon preserve live owners and pending state. Resume continues the same processes without reinitialization, duplicate delivery or scalar updates. Success requires all admitted jobs/waits/effects/responses and all credits, leases, descriptors, tree grants, scalar jobs, compute contexts and buffer generations to drain before exactly-once teardown. Idle-with-pending and cycle-limit outcomes are incomplete, never silent success. Liveness assumes finite accepted work, enabled draining sinks, finite positive service and no permanent failures. Directed temporary slowdowns are supported; disabled routes and permanent failures that violate these assumptions fail admission.

Add harness adapter `multicast_sync_v1`, independent normalizers/audits and a separate checked-in suite. Extend normalized observations with optional default-empty tree/destination/scalar structures only where existing events/effects cannot express them losslessly. Old v1 documents remain readable; omit empty extension fields in legacy adapter outputs so old raw results and stable digest fixtures do not change. Unknown new adapter names continue to fail in older binaries. Do not add multicast/scalar parameters to the existing calibration target allowlist in this child.

Oracles derive recipients and the corner/spine/branch edges directly from declared coordinates, reconstruct launched flits independently of producer totals, rebuild scalar state from initial values and ordered atomic effects, and verify release prerequisites/resource conservation. They must not call the production tree/packet/cost compiler. Corruption cases include duplicate/missing recipients, source inclusion errors, forged shared-prefix accounting, uncharged control traffic, duplicated scalar updates, response-before-effect, early wait release, stale generation, leaked reservations and self-consistent forged summaries.

Add `python -m simulator_detailed.replay_multicast_sync --workload ... [--output ...]` with JSON stdout, diagnostics stderr and exits 0 complete / 1 incomplete / 2 invalid or execution error. Admission and execution errors preserve an existing output file; completed/incomplete results publish atomically. Input/output alias protection follows the validation CLI. Add generic analytical, two-fabric/slowdown, finite-pipeline and explicit assumed Wormhole-profile examples. Legacy CLIs keep their current distinct exit conventions.

Capabilities list only the implemented subset after it executes. Existing cases continue to show unsupported multicast/sync when those cases do not use the new mechanisms; a new adapter's checks cannot globally mark every old run covered. External functional and silicon tiers remain unvalidated without admitted actual captures. Detailed detector/encoder guards reject the new kinds before model work, retaining 7-D/4-D shapes. Root RL observation/actions/checkpoints and the 4x4 Darknet19/failure workflow remain unchanged.

## Risks / Trade-offs

- [Tree reservation understates hardware control traffic or limits overlap] -> Report the centralized policy and assumed setup cost explicitly; charge physical data/response traffic exactly; avoid silicon latency claims.
- [New internal identities relax old validation] -> Keep old public envelope validators/version dispatch intact and compare predecessor output hashes/timelines after every shared-kernel change.
- [A slow branch retains unbounded copies or blocks unrelated classes] -> Charge every copy/token, keep output bitsets finite, use fair shared serializers and test capacity-one plus temporary slowdowns.
- [Multicast or waits create a hidden resource cycle] -> Combine tree grants, response provisioning, memory conflicts and slot/stage DAG checks; reject unsupported patterns and publish the proof assumptions alongside stress evidence.
- [Scalar service double-charges or bypasses L1] -> Use one indivisible shared-server job with a final configured duration and separate address/byte counters; test local/remote contention on both fabrics.
- [Synchronization masquerades as data visibility] -> Require local producer-version prerequisites or actual acknowledged completion followed by a modeled notification; corrupt those causal edges in oracle tests.
- [Planning completion is mistaken for delivery] -> Keep every task unchecked until implemented/verified; report parent coverage separately and leave umbrella reconciliation to the final audit.
